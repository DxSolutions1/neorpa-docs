# 문제 해결 / FAQ

자동화를 만들다 보면 자주 마주치는 상황들을 모았습니다. 각 항목은 **증상 → 확인 → 조치** 순서로 정리했습니다.

!!! tip "먼저 로그를 확인하세요"
    대부분의 문제는 하단 **출력** 패널의 실행 로그에 원인이 남습니다. 문제가 생기면 로그를 먼저 확인하는 습관을 들이면 원인을 훨씬 빨리 찾을 수 있습니다.

## 브라우저 확장이 연결되지 않을 때 { #browser-extension }

**증상**

- 웹(Chrome/Edge) 자동화 실행 시 "연결되지 않음(Disconnected)" 또는 브라우저와 통신하지 못한다는 메시지가 나타납니다.
- 요소 지시(Select)를 눌러도 브라우저 화면의 요소가 잡히지 않습니다.

**확인**

- 브라우저에 NeoRPA 전용 **확장 프로그램**이 설치·활성화되어 있는지 확인합니다.
- 자동화 대상 브라우저를 **전용 바로가기**(또는 리본의 `크롬 열기` / `엣지 열기`)로 실행했는지 확인합니다.
- 최초 1회 로컬 파일 배포(`CopyLocalFiles.bat`)를 실행했는지 확인합니다.

**조치**

1. 브라우저를 완전히 종료한 뒤 전용 바로가기로 다시 실행합니다.
2. 확장 프로그램을 껐다가 다시 켜거나, 재설치 후 화면 안내에 따라 등록을 완료합니다.
3. 그래도 안 되면 로컬 파일 배포 단계를 다시 실행하고 브라우저를 재시작합니다.

자세한 설치 순서는 [시작하기 — 브라우저 확장 설치](getting-started.md#browser-extension)를 참고하세요.

## 셀렉터가 요소를 찾지 못할 때 { #selector-not-found }

**증상**

- 실행 중 "요소를 찾을 수 없음"류의 메시지와 함께 액티비티가 실패합니다.
- 예전에는 되던 자동화가 화면이 바뀐 뒤로 실패합니다.
- 로그에 "이 액티비티의 셀렉터에는 대상 창/탭 정보가 없습니다"라는 오류가 남습니다.

**확인**

- 대상 화면(창·페이지)이 실제로 열려 있고, 요소가 화면에 보이는 상태인지 확인합니다.
- 페이지 로딩이나 화면 전환에 시간이 걸려서, 요소가 나타나기 전에 액티비티가 먼저 실행된 것은 아닌지 확인합니다.
- 요소의 이름·위치가 이전과 달라졌는지 확인합니다.
- 요소 편집기의 **검증(Validate)** 으로 현재 화면에서 몇 개의 요소가 일치하는지 확인합니다. 0개면 셀렉터가 낡았고, 2개 이상이면 셀렉터가 너무 느슨한 것입니다.

**조치**

1. 액티비티의 **대기 시간(요소 찾기 대기 시간 등)** 을 늘려 요소가 나타날 때까지 기다리도록 합니다.
2. **요소 지시(Select)** 를 다시 수행해 셀렉터를 최신 화면 기준으로 갱신합니다.
3. 데스크톱 화면에서 이름이 조금씩 바뀌는 요소라면 `클릭 V2`의 **유사 일치**(`EnableFuzzyMatching`)를 사용해 보세요. 임계값을 낮추면 더 느슨하게 찾습니다.
4. "대상 창/탭 정보가 없습니다" 오류는 창 정보가 빠진 부분 셀렉터가 스코프 밖에서 쓰인 경우입니다. 액티비티를 `창 연결 (스코프)` / `브라우저 연결 (스코프)` 안으로 옮기거나 요소 지시를 다시 수행하세요.

!!! note
    셀렉터가 무엇인지, 어떻게 요소를 지정하는지는 [기본 개념 — 셀렉터](concepts.md#selector)에서 설명합니다.

## 원격 데스크톱 자동화가 동작하지 않을 때 { #remote-desktop }

**증상**

- mstsc(원격 데스크톱) 창 안의 요소를 지시하거나 클릭·입력하는 자동화가 동작하지 않습니다.
- "mstsc 연결을 찾을 수 없습니다" 또는 "원격 머신이 응답하지 않습니다" 메시지가 나타납니다.

**확인**

- **원격 러타임(Remote Runtime)** 이 원격 머신에서 실행 중인지 확인합니다(트레이 아이콘 확인).
- 원격 데스크톱 연결이 유지되고 있고, 원격 세션이 **잠겨 있지 않은지** 확인합니다.
- 원격 데스크톱 자동화 기능이 설치·등록된 뒤에 mstsc를 다시 접속했는지 확인합니다.
- 원격 트레이 아이콘 **우클릭 → 로그 보기**로 호스트와의 연결(HELLO)이 기록되는지 확인합니다.

**조치**

1. 원격 머신에서 `install_remote.bat`을 다시 실행해 원격 러타임을 재시작합니다.
2. 열려 있던 mstsc 창을 모두 닫고 다시 접속합니다.
3. 원격 세션이 잠겨 있으면 잠금을 해제합니다(잠긴 상태에서는 입력이 전달되지 않습니다).
4. 그래도 해결되지 않으면 원격의 `%LOCALAPPDATA%\NeoRPA\remote-runtime-YYYY-MM-DD.log`와 호스트의 `%LOCALAPPDATA%\NeoRPA\rdp-plugin.log`를 확보해 관리자에게 전달합니다.

자세한 설치·테스트·제약은 [원격 데스크톱 자동화](remote-desktop.md)를 참고하세요.

## 실행이 시작되자마자 실패할 때 (로그 확인) { #logs }

**증상**

- 워크플로 실행 버튼을 누르자마자 곧바로 오류로 멈춥니다.
- 어느 액티비티에서 왜 실패했는지 화면만으로는 알기 어렵습니다.

**확인**

- 하단 `출력` 패널의 **실행 로그**에서 **Error** 또는 **Fatal** 수준의 줄과, 어떤 액티비티에서 멈췼는지 확인합니다. 로그 수준의 의미는 [기본 개념 — 로그 수준](concepts.md#log-level)을 참고하세요.
- 필요한 값(입력 텍스트, 파일 경로, 대상 요소 등)이 비어 있거나 잘못 지정되지 않았는지 확인합니다.
- 파일 경로를 상대 경로로 썼다면 기준이 **프로젝트 폴더**라는 점을 확인합니다.

**조치**

1. 로그의 오류 메시지를 읽고, 지목된 액티비티의 속성 값을 점검합니다.
2. 원인이 명확하지 않으면 리본의 `디버깅`으로 실행하고, 문제 지점에 **브레이크포인트**를 걸어 디버깅 패널의 **로컬** 탭에서 변수 값을 확인하며 한 단계씩(F6/F11) 진행합니다. 값을 고친 뒤 **현재 액티비티 재시도(F7)** 로 그 지점만 다시 실행해 볼 수 있습니다.
3. 파일·네트워크·권한 관련 오류라면 해당 자원이 실제로 접근 가능한 상태인지 확인합니다.

!!! tip
    실행과 디버그, 브레이크포인트, 디버깅 패널 사용법은 [기본 개념 — 실행과 디버그](concepts.md#run-debug)에서 설명합니다.

## 자주 묻는 질문

**Q. 만든 워크플로를 다른 PC에서도 쓸 수 있나요?**

프로젝트 폴더(`project.json`과 `.xaml` 파일들)를 통째로 복사해 다른 PC의 NeoRPA에서 **로컬 프로젝트 열기**로 열 수 있습니다. 단, 브라우저 자동화나 원격 데스크톱 기능을 쓰려면 그 PC에서도 해당 설치·설정 단계를 마쳐야 합니다.

**Q. 라이선스 코드를 잃어버렸어요.**

라이선스 코드는 조직의 담당자 또는 공급처를 통해 재발급받을 수 있습니다.

**Q. 화면이 바뀔 때마다 자동화가 자주 깨져요.**

이름·위치가 자주 바뀌는 요소는 셀렉터가 실패하기 쉽습니다. 안정적인 기준으로 요소를 다시 지정하고, 대기 시간을 충분히 두는 것이 좋습니다. 데스크톱 화면이라면 `클릭 V2`의 유사 일치도 도움이 됩니다.

**Q. 시작 화면을 건너뛰고 특정 프로젝트를 바로 열 수 있나요?**

명령줄에서 `open --project=<프로젝트 폴더>`로 실행하면 됩니다. [시작하기 — 명령줄로 열기·실행](getting-started.md#cli)을 참고하세요.
